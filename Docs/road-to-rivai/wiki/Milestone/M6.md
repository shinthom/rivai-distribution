# M6: Network Polish & Playable Loop

## 목표

M5에서 검증한 M1~M4 핵심 메커니즘을 **반복 플레이 가능한 2~8인 멀티 게임 루프**로 안정화한다. M6의 목표는 신규 고급 테크닉 추가가 아니라, Dedicated Server 기준에서 이동·전투·판정·라운드 흐름이 끊기지 않는 상태를 만드는 것이다.

## 선행 조건

- [ ] M5 Go 또는 Conditional Go 판정
- [ ] 4~8인 내부 테스트 로그 존재
- [ ] Ground / Air / Wall 이동 보정 이슈가 분류됨
- [ ] Slash / Block / Swap 판정 불일치가 재현 가능
- [ ] Dedicated Server 빌드·배포 루프 동작

## 핵심 산출물

- Network Correction Budget
- Lag Compensation 1차
- Hit Validation Audit
- Round / Spawn / Respawn 규칙
- Duel / Small Room 테스트 룰
- 최소 Scoreboard / Match State HUD
- 서버 로그 기반 Triage 리포트

## 포함 범위

| 기능 | 완료 기준 |
|---|---|
| Movement Reconciliation | Dash / Wall 보정 거리와 빈도 목표치 내 유지 |
| Lag Compensation 1차 | 50/100/150ms에서 Slash·Shot 판정 원인 추적 가능 |
| Combat Result Authority | 클라 예측과 서버 확정 결과가 HUD·로그로 구분됨 |
| Match State | Warmup / Playing / RoundEnd / Reset 전이 동작 |
| Spawn / Respawn | 라운드 테스트 중 즉시 재진입 가능 |
| Scoreboard | Kill / Death / Ping / Build 표시 |
| Playtest Loop | 30분 반복 플레이 후 재현 가능한 이슈 목록 생성 |

## 제외 범위

Butterfly, Slashshot, Reload Shot, Half Step 같은 고급 GunZ-style 테크닉 완성, 정식 매치메이킹, 계정, 랭킹, 상용 안티치트, 정식 UI/UX, 콘텐츠 밸런스 완성.

## 네트워크 안정화 기준

```text
Target Profile:
- 2인 Duel: 100ms / 1% loss에서 치명적 Desync 없음
- 4인 Room: 100ms / 1% loss에서 30분 플레이 가능
- 8인 Room: 50ms / 0~1% loss에서 서버 Tick 급락 없음
- Movement Correction: 원인·거리·빈도 로그화
- Combat Mismatch: Hit / Block / Swap 불일치 재현 절차 확보
```

## 구현 방향

- `FSavedMove_Character`와 `FCharacterNetworkMoveData` 확장 값을 실제 UE 5.7.4 API 기준으로 정리
- Movement Correction을 Dash / AirDash / WallRun / WallJump 별로 분리 집계
- 서버 시간 기준 판정창과 클라이언트 예측 연출을 명확히 분리
- Trace 기반 공격은 서버 기준 결과 확정, 클라는 예측 표시만 수행
- Reliable RPC는 라운드 시작·종료·중요 이벤트에만 사용
- 반복 테스트 가능한 라운드 규칙을 먼저 만들고, 정식 UX는 뒤로 미룸

## Match State

```text
Boot
 └─ Warmup
     └─ Countdown
         └─ Playing
             ├─ RoundEnd
             └─ SuddenReset
```

## Debug HUD 예시

```text
Match: Playing | Round: 03 | Time: 02:18
Score: 7 / 5 | K/D: 4/2 | Ping: 86ms
Move Correction: WallRun 3 | Max Error: 42.1
Hit Validation: Pending 1 | Mismatch 0 | Server Tick: 60
```

## 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 고속 이동 보정이 체감을 망침 | 보정 거리·빈도 예산을 수치화하고 초과 케이스만 튜닝 |
| Lag Compensation 범위 과대 | 1차는 Shot / Slash 판정 원인 추적과 제한적 보정에 집중 |
| 라운드 룰 구현이 UI 작업으로 비대화 | 텍스트 HUD와 콘솔 로그 중심으로 제한 |
| 8인 테스트에서 Replication 비용 증가 | Replication Graph / Iris 검토 조건을 로그 기준으로 판단 |
| 전투 예측과 서버 확정 불일치 | 예측 연출과 확정 피해를 별도 상태로 표시 |
