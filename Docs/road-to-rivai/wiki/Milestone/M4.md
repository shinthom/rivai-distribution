# M4: Combat & Cancel Window

## 목표

M1~M3 이동 위에 GunZ-like 전투의 최소 단위를 얹는다. 무기 밸런스가 아니라, 이동 중 공격·방어·전환이 가능한 입력 체계와 서버 검증 가능한 전투 상태 구축.

## 선행 조건

- [ ] M3 Wall Run/Jump 완료
- [ ] 이동 상태가 HUD에 표시
- [ ] Dedicated에서 이동 콤보 관찰 가능
- [ ] Movement State와 전투 입력 분리

## 핵심 산출물

- Slash / Block / Weapon Swap
- Ranged Weapon Placeholder
- Cancel Window 규칙
- Combat State Debug HUD
- Melee·Ranged Hit Trace 초안
- 피격·방어·전환 로그

## 포함 범위

| 기능 | 완료 기준 |
|---|---|
| Slash | 판정과 애니메이션 타이밍 분리 추적 |
| Block | 성공·실패 로그 |
| Weapon Swap | 전환 가능 상태 명확 |
| Cancel Window | HUD에 상태·Window 표시 |
| Basic Hit Validation | 클라 단독 피해 확정 없음 |

## 제외 범위

정교한 무기 밸런스, 다양한 총기·스킨, 랙 보정 완성, 상용 안티치트, 킬캠·리플레이, 랭킹·매치메이킹.

## 구조

```text
AGZPlayerCharacter
 ├─ UGZCharacterMovementComponent
 ├─ UGZCombatComponent
 │   ├─ Combat State
 │   ├─ Weapon State
 │   ├─ Cancel Window
 │   ├─ Hit Validation
 │   └─ Server RPC
 └─ UGZWeaponComponent
```

## Combat State

```text
None ─ SlashWindup ─ SlashActive ─ SlashRecovery
     ─ BlockEnter ─ Blocking ─ BlockExit
     ─ WeaponSwap
     ─ Stunned / HitReact
```

## Cancel Window 예시

```text
Slash      → Block     : allowed during SlashRecovery
Slash      → WeaponSwap: allowed after ActiveWindow ends
Dash       → Slash     : allowed after DashLockout
WallJump   → Slash     : allowed if AirCombatEnabled
Block      → Dash      : allowed after BlockExit
WeaponSwap → Slash     : allowed when SwapCommit reached
```

## 서버 검증 원칙

- 전투 결과는 서버 확정
- 클라이언트는 입력 반응·애니메이션 예측만
- 피해·Block·탄환 적중·Slash Hit는 서버 검증
- Slash 판정은 Animation Notify에 의존하지 않고 서버 시간 기준 Active Window
- Swap·Cancel Window는 상태머신 또는 GameplayTag로 명시

## Debug HUD 예시

```text
Combat State: SlashActive | Weapon: Katana | Prev: ShotgunPlaceholder
Cancel: SlashToBlock=true | Hit Window: active | Block: false
Server Confirmed Hit: pending | Last Hit: none
```
