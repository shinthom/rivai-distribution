# M5: Network Combat Test

## 목표

M1~M4 메커니즘을 Dedicated Server에서 검증한다. 완벽한 네트워크 완성이 아니라, 핵심 메커니즘이 멀티플레이에서 가능한지 판단 가능한 데이터·테스트 결과 확보.

## 선행 조건

- [ ] M0 배포·피드백 루프 동작
- [ ] M1 Ground Dash
- [ ] M2 Air Dash / Wall Detection
- [ ] M3 Wall Run / Wall Jump
- [ ] M4 Slash / Block / Weapon Swap
- [ ] Dedicated Server 빌드 가능

## 핵심 산출물

- Dedicated 빌드·운영 절차
- 4~8인 내부 테스트
- 이동·전투 동기화 검증
- Hit Validation
- Network Emulation 테스트
- Profiler·로그 수집
- 버그 Triage
- Public Alpha 전 체크리스트

## 포함 범위

| 기능 | 완료 기준 |
|---|---|
| Server Authority | 클라 단독 피해 확정 없음 |
| Movement Prediction Audit | 보정 로그·재현 조건 |
| Combat Validation | 2인 이상 결과 일관 |
| Lag Test | 50/100/150ms + Packet Loss |
| Performance Budget | Tick·Bandwidth·FPS 측정 |
| Playtest Loop | 시나리오·피드백 양식 운영 |

## 제외 범위

Public Alpha 운영, 계정·매치메이킹·랭킹, 상용 안티치트, 대규모 서버 자동화, 전체 밸런스, 정식 UI/UX.

## 테스트 구조

```text
Build   : Client / Server / manifest.json / patch-notes
Env     : Test Server 01 / UDP 7777 / Server Logs / Build Version / Network Emulation
Tester  : Launcher Update ➔ Play ➔ Join ➔ Scenario ➔ Feedback + Logs
```

## 네트워크 지표

| 지표 | 목적 |
|---|---|
| Ping | 지연 환경 분류 |
| Packet Loss | 이동·전투 유지 여부 |
| Correction Count / Distance | 보정 빈도·심각도 |
| Server Tick Rate | 처리 안정성 |
| Bandwidth per Player | 복제 비용 |
| RPC Count | 호출 과다 여부 |
| Hit Validation Fail Rate | 판정 불일치 |
| Crash / Disconnect | 안정성 |

## 플레이테스트 시나리오

| Scenario | 인원 | 합격 기준 |
|---|---:|---|
| Connection Smoke | 2 | 5분 무오류 |
| Movement Sync | 2~4 | 치명적 Desync 없음 |
| Duel | 2 | 양측 동일 결과 |
| Small Room | 4~8 | 30분 테스트·로그 가능 |
| Latency | 2~4 | 50/100/150ms 분류 |

## 지연 프로파일

```text
A: 0~30ms,  0%      loss
B: 50ms,    0~1%    loss
C: 100ms,   1~2%    loss
D: 150ms,   2~5%    loss
E: unstable, spike simulation
```

각 프로파일에서 Correction Count, Slash·Block 불일치, Swap 상태 불일치, Crash, 플레이 가능 여부 기록.

## 구현 방향

- Dedicated 기준 테스트, Listen Server는 보조
- Replication / RPC / Movement Correction / Network Profiler로 병목 확인
- 인원 증가 시 Replication Graph 또는 Iris 검토
- Hit Validation은 서버 기준, Lag Compensation 범위 정의
- 목표는 "완벽한 네트워크"가 아닌 "핵심 메커니즘의 멀티플레이 가능성 검증"

## 체크리스트

- [ ] 클라/서버 버전 불일치 경고

## Go / No-Go

| 판정 | 조건 |
|---|---|
| Go | 4~8인 핵심 루프 플레이 가능, 이슈가 수정 가능한 수준 |
| Conditional Go | 가능성은 있으나 보정·판정 문제 잦음 → M6를 Network Polish로 |
| No-Go | Dedicated에서 Dash·Wall이 반복 Desync, 핵심 재미 불가 |

## 완료 기준

- [ ] 4~8인 핵심 루프 플레이 가능
- [ ] 치명적 Desync·Crash·입력 불능이 Known Issues로 분류
- [ ] Go / No-Go 결정 가능
- [ ] Public Alpha를 위한 후속 마일스톤 정의
