# M0: Test Distribution Pipeline

## 목표

팀원이 홈페이지에서 런처를 받아 최신 빌드를 설치·실행하고, 테스트 서버에 접속해 피드백·로그를 제출할 수 있게 한다. M0는 게임 콘텐츠가 아니라 M1~M5를 반복 테스트 가능하게 만드는 시스템이다.

## 완료 한 줄

> 팀원이 새 PC에서 홈페이지 ➔ 런처 ➔ 설치 ➔ Play ➔ 테스트 서버 접속 ➔ Build Version 확인 ➔ 피드백·로그 제출까지 수행할 수 있다.

## 포함 범위

| 항목 | 목적 |
|---|---|
| 홈페이지 v0 | 다운로드·패치노트·가이드·피드백 링크 |
| 런처 v0 | 최신 빌드 다운로드·업데이트·실행 |
| `manifest.json` | 버전·URL·sha256·서버 주소 관리 |
| 빌드 저장소 | 클라/서버 zip 보관 |
| 테스트 서버 | 고정 접속 서버 1개 |
| 피드백 폼 | 버그·조작감·네트워크 수집 |
| 로그 수집 | Logs 폴더 열기, Build Info 복사 |
| 패치노트 | 빌드별 변경 사항 |
| 빌드 자동화 초안 | 반복 가능한 BuildCookRun |

## 제외 범위

| 제외 | 이유 |
|---|---|
| 회원가입/로그인 | 배포 우선 |
| 결제·랭킹·매치메이킹 | 프로토타입 비핵심 |
| 차등 패치 | 초반엔 전체 zip이면 충분 |
| 상용 안티치트 | M5 이후 별도 마일스톤 |
| 화려한 홈페이지 | 테스터 포털 역할이면 충분 |

## 초기 결정

| 항목 | 결정 |
|---|---|
| 플랫폼 | Windows, Mac |
| 인증 | 로그인 없음 (필요 시 공유 비밀번호) |
| 배포 | 전체 zip 다운로드 |
| 업데이트 | `Version.txt` vs `manifest.latestVersion` 비교 |
| 서버 | 고정 1개. M0.1은 Listen 허용, M0.3부터 Dedicated |
| 피드백 | Google Form / Notion / Discord 중 택1 |
| 로그 제출 | Logs 폴더 열기 |
| 런처 | C# WPF 또는 WinUI |
| 홈페이지 | 정적 사이트 |
| 빌드 | 수동 → BuildCookRun 스크립트화 |

## 흐름

```text
Dev ➔ Client/Server Build ➔ 압축 ➔ Storage 업로드 ➔ manifest.json 갱신
   ➔ Homepage/Launcher 인식 ➔ Tester 다운로드·실행
   ➔ Test Server 접속 ➔ Feedback·Log 제출
```

## 세부 마일스톤

### M0.1 — Manual Distribution
홈페이지에서 수동 zip 다운로드 가능.
- [ ] 팀원이 링크만으로 실행 가능
- [ ] 게임 내 Build Version 확인
- [ ] 피드백 폼에 Build Version 입력

관련 Task: [[C01-manual-distribution|C01 — Manual Distribution]]

### M0.2 — Launcher v0
런처가 최신 빌드를 자동 다운로드·실행.
- [ ] zip을 직접 다루지 않고 런처로 실행
- [ ] 런처가 최신 vs 설치 버전 비교
- [ ] 런처에서 게임 실행

관련 Task: [[D01-launcher-v0|D01 — Launcher v0]]

### M0.3 — Test Server
동일 서버에 팀원 접속 가능.
- [ ] 런처로 실행한 클라이언트가 테스트 서버 접속
- [ ] 2인 이상 동시 접속
- [ ] 서버 로그 위치 문서화

관련 Task: [[E01-test-server|E01 — Test Server]]

### M0.4 — Feedback Loop
처리 가능한 형태로 피드백 수집.
- [ ] Build Version·재현 절차·로그 포함
- [ ] 테스터가 Logs 폴더를 찾을 수 있음
- [ ] 개발자가 발생 버전 추적 가능

관련 Task: [[F01-feedback-and-log-loop|F01 — Feedback and Log Loop]]

### M0.5 — Build Automation
빌드·배포를 반복 가능한 작업으로 표준화.
- [ ] 새 빌드 배포 절차 동일
- [ ] 런처가 신규 빌드 감지
- [ ] 패치노트 자동 기록

관련 Task: [[G01-build-automation-draft|G01 — Build Automation Draft]]

## manifest.json 예시

```json
{
  "project": "GZ Prototype",
  "channel": "dev",
  "latestVersion": "0.0.1-dev",
  "buildId": "2026.05.17.001",
  "downloadUrl": "https://example.com/builds/GZPrototype_Client_0.0.1_dev.zip",
  "sha256": "PUT_SHA256_HASH_HERE",
  "sizeBytes": 1500000000,
  "executable": "GZPrototype.exe",
  "server": { "name": "Test Server 01", "host": "test.example.com", "port": 7777 },
  "patchNotesUrl": "https://example.com/patch-notes",
  "feedbackUrl": "https://example.com/feedback"
}
```

## BuildCookRun 예시

```bat
:: Client
RunUAT.bat BuildCookRun -project="...\GZPrototype.uproject" -noP4 ^
 -platform=Win64 -clientconfig=Development ^
 -build -cook -stage -pak -archive ^
 -archivedirectory="D:\Builds\GZPrototype\Client"

:: Dedicated Server
RunUAT.bat BuildCookRun -project="...\GZPrototype.uproject" -noP4 ^
 -server -serverplatform=Win64 -serverconfig=Development -noclient ^
 -build -cook -stage -pak -archive ^
 -archivedirectory="D:\Builds\GZPrototype\Server"
```

## 피드백 폼 항목

Tester Name, Build Version, Build ID, Test Date, PC Spec, Ping, What did you test, Bug/Feedback Type, Steps to Reproduce, Expected/Actual Result, Screenshot URL, Log Attached.
