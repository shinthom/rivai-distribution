1/ Cloudflare R2나 AWS S3 같은 객체 스토리지는 우리가 쓰는 Windows/Mac의 폴더 구조와 완전히 다르다. 디렉토리라는 개념이 없고, 실제로는 `Key`와 `Value`로만 이루어진 거대한 평면(Flat) 키-값 저장소다.

2/ 우리가 `builds/dev/client/game.zip` 구조로 저장하더라도, 스토리지 입장에서는 폴더가 아니라 `builds/dev/client/game.zip`이라는 '슬래시(/)가 포함된 하나의 긴 이름(Key)'을 가진 객체일 뿐이다. 이 개념을 알아야 추후 코드나 CLI로 파일을 제어할 때 경로 실수를 안 한다.

3/ 마지막으로, `manifest.json`을 업로드할 때는 반드시 HTTP 헤더의 `Content-Type`을 `application/json`으로 명시해 줘야 한다. 객체 스토리지는 이 메타데이터를 함께 저장하는데, 이게 누락되거나 다르면 런처나 웹 브라우저가 이 파일을 JSON 데이터가 아닌 일반 텍스트나 다운로드용 파일로 오인해 파싱 에러를 낸다.
