1/ 배포 자동화(CI/CD)를 짤 때 절대 어기면 안 되는 철칙이 있다. 반드시 새 `zip` 파일을 스토리지에 먼저 완전히 업로드한 뒤, 맨 마지막에 `manifest.json`을 단 한 번의 요청으로 갱신해야 한다.

2/ 만약 반대로 `manifest.json`을 먼저 수정하면 치명적인 레이스 컨디션(Race Condition)이 발생한다. 전 세계의 런처들이 "오! 새 버전 나왔다" 하고 manifest에 적힌 `downloadUrl`로 몰려들겠지만, 정작 `zip` 파일은 아직 업로드 중이라 `404 Not Found` 에러를 만나며 배포 장애로 이어진다.

3/ 추가로, 이미 배포된 특정 버전의 `zip` 파일은 절대 내용을 수정해서 덮어쓰면 안 된다. 빌드 내용이 단 한 바이트라도 바뀌었다면, 무조건 새 버전 번호를 부여하거나 `buildId`를 올려서 새 파일로 업로드해야 `sha256` 값과 CDN 캐시의 일관성이 유지된다.
