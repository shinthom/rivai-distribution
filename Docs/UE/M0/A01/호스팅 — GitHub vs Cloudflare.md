1/ 어떤 호스팅 인프라를 선택해야 하는가

게임 빌드와 `manifest.json`을 어디에 올릴지 결정해야 한다. 인프라의 특성에 따라 추후 서비스 확장성과 운영 비용이 완전히 달라지므로 프로젝트의 목적에 맞는 선택이 필요하다.

2/ 옵션 A: GitHub 통합 (Pages + Releases)

인프라 구성이 가장 쉽다. GitHub Pages에 manifest를 두고, Releases에 빌드 zip을 첨부하는 방식이다. 추가 계정 생성 없이 Git 워크플로만으로 완결되며 무료라는 강력한 장점이 있다.

3/ GitHub 통합의 한계

단점도 명확하다. Release 자산은 파일당 2GB 제한이 있어 게임 용량이 커지면 막힌다. 또한 글로벌 다운로드 속도가 들쭉날쭉하고, 테스터에게만 빌드를 숨기는 '비공개 배포' 구현이 까다롭다.

4/ 옵션 B: Cloudflare 통합 (Pages + R2)

프로젝트 확장과 학습을 위해 가장 추천하는 구조다. 정적 사이트(Pages)와 객체 스토리지(R2)를 분리한다. 특히 R2는 AWS S3와 달리 Egress(외부 전송) 비용이 완전 무료라 테스터가 늘어도 비용 폭탄이 없다.

5/ Cloudflare 통합을 추천하는 이유

R2는 업계 표준인 AWS S3 API와 호환되므로 한 번 배우면 다른 클라우드로 이식이 쉽다. 추후 Cloudflare Workers를 얹어 '인증된 테스터만 다운로드 허용' 같은 고급 제어를 쉽게 확장할 수 있다는 점도 크다.
