1/ 정적 사이트와 큰 zip을 같이 호스팅할 때, GitHub Pages + Releases와 Cloudflare Pages + R2 중 무엇이 더 나은가? 무료 한도와 단순함만 보면 GitHub이 매력적이지만, '스케일이 커졌을 때의 청구서'를 보면 결정적인 차이가 있다.

2/ GitHub Releases는 asset당 2GB 한계가 있고, 다운로드 속도가 보장되지 않으며, 많은 트래픽이 몰리면 GitHub이 자체적으로 한도를 두기도 한다. 더 큰 문제는 Egress(외부 다운로드 트래픽)다. AWS S3 같은 보통의 객체 스토리지는 다운로드 1GB당 약 $0.09를 부과한다. 5GB 빌드를 100명이 받으면 $45.

3/ Cloudflare R2의 차별점은 'Egress 무료'다. 저장 비용(월 GB당 약 $0.015)과 요청 비용만 든다. 같은 5GB × 100명 시나리오에서 R2는 사실상 0원. 빌드가 커지고 테스터가 늘수록 두 옵션의 차이는 폭발적으로 벌어진다.

4/ 두 번째 이득은 API 호환성이다. R2는 S3 API와 호환되므로 한 번 배운 도구(`wrangler`, `aws-cli`, 각종 S3 SDK)가 그대로 통한다. 추후 AWS S3나 Backblaze B2 같은 다른 공급자로 옮길 때 코드 변경이 거의 없다 — 학습이 그대로 자산이 된다.

5/ 정리: 빌드 크기가 작고 테스터가 소수면 GitHub로 충분하다. 하지만 '게임 배포'처럼 처음부터 큰 zip이 예상되고 사용자가 늘어날 가능성이 있으면 R2가 정답이다. 우리는 R2를 선택했고 M0에서는 도메인 없이 `pub-<hash>.r2.dev` 서브도메인을 그대로 쓴다. 도메인은 추후 manifest의 `downloadUrl` 값만 교체하면 끝나서 부담 없는 결정이다.
