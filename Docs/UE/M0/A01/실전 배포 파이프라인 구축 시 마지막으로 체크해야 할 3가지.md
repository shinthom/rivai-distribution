1/ `A01 Task`를 완벽하게 끝내기 위해 마지막으로 점검해야 할 실전 지식이다. 툴을 다루는 단계를 넘어, 실제 자동화(G01)와 클라이언트(D01)가 붙었을 때 발생할 병목을 미리 방지하는 3가지 핵심 포인트를 요약한다.

2/ **① CORS(교차 출처 자원 공유) 설정 문제**

웹 홈페이지(B01)에서 R2에 있는 `dev.json`을 `fetch()`로 읽어와 최신 버전을 표시하려 할 때, 높은 확률로 CORS 에러를 만나게 된다. 보안을 위해 브라우저가 다른 도메인의 자원 접근을 막기 때문이다. R2 버킷 설정에서 홈페이지 도메인에 대한 `GET` 요청 CORS 허용 정책을 미리 심어두어야 한다.

3/ **② 오프라인 검증용 `Version.txt` 전략**

런처가 매번 몇 기가씩 되는 대용량 `zip`을 받아서 `sha256`을 돌리는 것은 디스크 IO와 CPU 소모가 크다. 이를 최적화하기 위해, 압축을 푼 로컬 폴더에 `Version.txt`를 남겨두는 구조가 필수적이다. 런처는 최초 실행 시 이 가벼운 텍스트 파일만 읽어 manifest와 비교하고, 값이 다를 때만 전체 무결성 검증과 패치를 수행한다.

4/ **③ 대용량 빌드 파일 업로드의 한계 (`wrangler` 청크 관리)**

나중에 실제 Unreal 빌드가 나와서 `zip` 파일이 수십 기가바이트(GB)로 커지면, 일반적인 단일 HTTP PUT 요청은 네트워크 불안정으로 무조건 터진다. CLI 환경이나 CI/CD 스크립트에서 R2로 대용량 파일을 올릴 때는 반드시 파일을 조각내어 올리는 '멀티파트 업로드(Multipart Upload)' 옵션을 활성화해야 파이프라인이 멈추지 않는다.
