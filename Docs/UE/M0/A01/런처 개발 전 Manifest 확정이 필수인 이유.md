1/ Unreal로 게임을 잘 만드는 것과 유저에게 안전하게 배달하는 것은 별개다. 안정적인 배포 파이프라인 구축을 위해 `manifest.json` 규격 확정이 왜 필수인지 요약한다.

2/ 런처의 본질은 버전 비교와 다운로드다. JSON 필드가 먼저 정의되어야 게임 개발 상황과 의존성 없이 런처의 핵심 패치 로직을 독립적으로 선개발할 수 있다.

3/ **패치 시 런처와 홈페이지는 동일한 곳을 바라봐야 한다.** 하나의 공통 manifest를 두면, 파일 하나만 업데이트해도 모든 플랫폼이 휴먼 에러 없이 동시 동기화된다.

4/ 대용량 게임 파일은 다운로드 중 깨지기 쉽다. 빌드 시 `sha256`과 용량을 기록해두면, 런처가 자체 검증하여 "실행 불가" 같은 유저측 오류를 원천 차단한다.

5/ 서버 IP나 피드백 링크를 클라이언트에 하드코딩하면 수정할 때마다 재빌드·재배포해야 한다. 이를 manifest로 분리하면 클라이언트 수정 없이 실시간 제어가 가능하다.
